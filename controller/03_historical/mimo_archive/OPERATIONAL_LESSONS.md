## 1. Execution method (the operating loop)

**L-1 · Local-first development, bounded remote use.** `local edit → local test → local browser/render → local screenshot → compare → fix → repeat`; managed/remote execution only for genuinely unavailable capabilities, independent corroboration or target-platform proof. "GitHub Actions must not become the ordinary development workstation." (lessons ledger §G "Local-first development reduces managed-runner overuse")
**L-2 · Post-download verification is mandatory.** Workflow green is insufficient. Any consumed artifact must independently pass SHA/bytes, ZIP/CRC, standalone verifier, `git bundle verify`, materialization to exact HEAD/tree, clean worktree, Product identity and mission input verification. (§G "Post-download verification is mandatory")
**L-3 · Product parent ≠ transport identity.** A capsule/commit carries at least two identities: accepted Product parent/source and the transport commit/tree carrying mission/harness/manifest material. Never measure Writer Product delta from the transport baseline; capsule prep may legally change transport files while Product delta is zero. (§G)
**L-4 · Correction continuity.** Once a candidate is independently reconstructed/audited and retained as a salvageable base, continue incrementally (same clean worktree, or deterministic reconstruction from nearest verified base + ordered delta/bundle chain + lightweight continuation overlay) instead of repackaging a full capsule per Writer result. Preserve predecessors immutably; emit successors; never overwrite or sibling-overlay. (§G "Correction continuity"; register OD-20260922-076)
**L-5 · Visual Bootstrap is an acceleration input, not final evidence.** Bootstrap screenshots must be exact-source-bound and actually inspected; an `import-open` screenshot can be byte-identical to default when the state sits below the viewport — open/hash presence is not enough. Capture important states visibly; Writer fresh-recaptures after Product mutation. (§G)
**L-6 · Bounded Controller correction is a throughput tool, not feature authority** (OD-20260916-044): exact reproduction, minimal existing-owner diff, isolated candidate, full affected revalidation; never broad feature work/new architecture/new owner/scope widening. (§G)
**L-7 · Writer result custody under capsule method.** Intermediate screenshots/diffs/logs/videos = local scratch; GitHub carries Product source/delta + small bounded receipts; heavy final generated/candidate/evidence custody → Drive. A Writer result may arrive as a Drive final handoff rather than a pushed branch; verify exact bundle/source ancestry before acceptance. (§G)
**L-8 · Do not mutate Product to satisfy stale evidence.** Classify first (Product / harness / evidence-receipt / environment-platform / package-manifest / provider-data); exact-current Product truth outranks stale test assumptions. (§G; handoff §13)

## 3. Review and audit discipline

**L-9 · Never trust surface signals.** Writer PASS, Helper PASS, screenshots, green tests, filenames, folder presence, branch presence — none is authority. Result-first order: Writer → exact custody → identity/ancestry/scope → package/manifest → direct falsification → browser/runtime/visual → Owner-decision zero-loss → reuse/duplicate-owner → Data/Provider/Persistence → integrated regression → disposition. (handoff §14)
**L-10 · Reviewer verdict cannot outrank its own evidence.** If evidence records BLOCKED/PARTIAL/unavailable, a later `VISUALLY_VERIFIED_CLEAN`/`CLEAN_FOR_CONTROLLER_ADJUDICATION` label requires a new traceable evidence chain. (lessons §O)
**L-11 · Canonical finding identity includes meaning, not only the ID string.** Reusing `Axx-PF-xxx` for a different issue does not close the canonical finding; closure binds original wording/meaning, exact source seam, positive proof, negative proof, final disposition. (§O)
**L-12 · Domain-level success ≠ Product-command reachability.** A direct `domain.publish()` can pass while the composed Product command bus exposes no publish command; lifecycle acceptance tests the real composed route. (§O)
**L-13 · Strict DI verified at the highest composition actually instantiated.** Children may fail closed while a group composition silently constructs `new SemanticCommandBus()`/`new AnalyticalCompareOwner()`; duplicate-owner review must inspect top/group composition and the real m0/main caller. (§O)
**L-14 · Preserve validated value while repairing narrow root causes.** A later defect is not authority to revert an entire lineage (Structured/Sticky reuse, Today epistemic states, Canvas semantics, operational owner boundaries, shared replay/compare owners, provider safety were explicitly preserved). (§O)
**L-15 · Grouping is scheduling, not gate deletion.** D12 (pre-integration collision/falsification), D13 (serialized shared-hotspot integration), D14 (post-integration independent proof) remain distinct semantic gates even when compressed into fewer missions. (§O)
**L-16 · Helper/audit roles are bounded.** Helper chats are packet builders, not co-equal Controllers; they own no acceptance, CURRENT_STATE, governance, COMMON_AND_DAG, convergence or launch authority. Helper presence/folder counts are never completion authority. (handoff §17.2; `CURRENT_STATE.md` Stage-3 entries)

## 4. Continuity, custody and lost-WIP law

**L-17 · Heavy-chat checkpoint (OD-20260916-042).** On explicit Owner checkpoint request: materialize `CONTINUITY_CHECKPOINT_CURRENT/` + `CEP_HEAVY_RESUME_CHECKPOINT_CURRENT.zip` with `CHECKPOINT_RECEIPT.json, WORKING_CANDIDATE.zip, HANDOFF.md, APPLIED_CHANGE_LEDGER.json, SOURCE_DIFF.patch, FINDING_LEDGER.json, PHASE_PROGRESS.json, TEST_EVIDENCE_INDEX.json, REVALIDATION_MAP.json, INPUT_CONSUMPTION.json, OWNER_DECISION_PROGRESS.json, RESUME_INSTRUCTIONS.md`. Custody class `CANDIDATE_ONLY / NOT_ACCEPTANCE / NOT_PROMOTION / NOT_MAIN / NOT_RELEASE / NOT_DEPLOYMENT`. Checkpointing is continuity transport, not acceptance. (handoff §9)
**L-18 · Drive-first lost-WIP law.** For a vanished worktree/commit: inspect exact Surface folder, WRITER_OUTPUT, bounded children, artifact IDs from handoff/manifest/receipt **before concluding loss from GitHub alone**. Recoverable custody requires source-bearing bytes (candidate/source ZIP, git bundle, exact snapshot, or ordered reconstruction chain with verifiable identity). Screenshots/logs/prose/hash text = `EVIDENCE_ONLY__NOT_RECOVERABLE_PRODUCT_SUCCESSOR`. No exact successor ⇒ OD-076 path C (new full capsule/base + re-execute current zero-loss obligations). Never reconstruct lost source from chat memory. Known checked examples: Validation and Manual-AI WRITER_OUTPUT empty; Health held predecessor handoff evidence only; Scenarios later Phase-2 WIP unrecoverable (frozen delta salvage only); Labs latest Phase-2 patch-only. (handoff §10; `CURRENT_RESULT_AUDIT.txt`)
**L-19 · Succession closeout transfers decision method, not just state.** Live authority/identity, exact pending task + stop point, source-proven vs unproven findings, failure classification method, carrier separation, mission holds/locks, next diagnostic action, negative requirements and acceptance ceilings. Update stable succession files in place; don't create a new Owner decision merely because a chat changes (OD-077 governs). (§L)
**L-20 · First-successor action pattern.** Mandatory boot → recheck every contacted Writer chat + bound Drive output folder for newer results → request Heavy-Chat checkpoints for live WIP → classify each result `RECOVERABLE_VERIFIED_SUCCESSOR / RECOVERABLE_SALVAGEABLE_DELTA / UNTRUSTED_OR_INCOMPLETE_WIP / NO_DURABLE_RESULT` → update CURRENT_STATE with a recovery intake matrix → only then prepare zero-loss continuation/fallback packets. Do not open fresh Writer chats merely because old chats are long. (handoff §8)

## 6. Governance-operational lessons

**L-26 · Carrier separation.** Mission/DAG scope and execution-carrier topology are independent; `ROUTE-LOCAL`/ChatGPT/AI-Studio/MIMO carriers have different branch, seriality, path, shell/runtime, client/model, push and evidence-custody rules. Never copy `writer/cep-serial`, Kimi/local Windows details or task-specific no-push rules across carriers without an explicit rebind. (lessons §K; `EXECUTION_CARRIER_ROUTE_AUTHORITY.txt` §1)
**L-27 · ROUTE-LOCAL remote write is default-deny.** Local checkpoint creation and remote publication are separate truths (OD-20260925-083); historical push permission and task completion do not carry forward. (lessons §O)
**L-28 · Repository cleanup ≠ final historical slimming.** Dependency-aware reduction; governed visual references (28 PNGs) are Writer inputs, not removable "screenshots"; current-tip size ≠ Git-history size; cleanup validation must preserve open truth gates; recorded progression 1,540 → 1,517 → 1,154 files with Product source byte-identical. (lessons §I; `CURRENT_STATE.md`)
**L-29 · Owner-input routing (OD-20260922-079).** Classify before writing: task sequencing→Mission/CURRENT_STATE; current facts→CURRENT_STATE; enhancements→backlog; defects/QA/rejections→finding custody; evidence→evidence custody; reusable lessons→stable references; profile/domain→profile/oracle/intake. Ambiguity forbids decision-register inflation. (lessons + `READ_FIRST.md`)
**L-30 · Mission packet scope contradiction debt.** Where machine-readable `CAPSULE_BINDING` scope is broader than prose `MISSION.md`, treat as `MISSION_PACKET_SCOPE_CONTRADICTION`/mission-design debt (not Writer misconduct) and make prose + machine scope identical in future packets. (`CURRENT_RESULT_AUDIT.txt` cross-cutting C)
