## 2. Explicit negative findings (no invented placement)

1. There is **no** `stack/native-typescript/surfaces/health/` and **no**
   `stack/native-typescript/surfaces/processing/` today. HEALTH and PROCESSING are the only two of
   the 23 surfaces whose presentation lives inside a **runtime adapter module** (`adapters/*-runtime.ts`)
   instead of a `surfaces/<name>/` directory; they are mounted generically by
   `m0-controller-composition.ts` L241 via the adapter's own `mount()` method.
2. There is **no** `stack/native-typescript/adapters/surfaces/` directory and therefore no
   `health-domain.ts` / `processing-domain.ts` file, despite `contracts/SURFACE_READINESS_REGISTRY.json`
   declaring those exact paths (see conflicts file C-06).
3. "Blueprint → Production conversion" has **no W01 (shell/today) implementation** and no global
   foundation module. The only executable artifact is the Library-donor-local
   `CONVERSION_COMPATIBILITY` / `production-mapping-manifest` machinery in `accepted-runtime.ts`,
   and SC-039 `ProductionMappingBoundary` is contract-only (`contracts/CORE_OWNER_REGISTRY.json`).
4. The profile-declared bottom tab `domain-diagnostics` (all 23 profiles, `bottom_tabs` field) has
   **no implementation**; the shared bottom deep-work shell exposes `history/compare/recovery`
   (`bottom-shelf.ts` L22).
