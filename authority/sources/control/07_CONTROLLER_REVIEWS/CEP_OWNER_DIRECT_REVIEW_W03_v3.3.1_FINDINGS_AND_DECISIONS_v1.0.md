## 3. Root-cause conclusion
The main failure is **evidence over-closure**: in multiple areas the presence of a control, selector, handler, state key, or reconciled row was treated as implementation completion even when the user-visible state transition was absent, ambiguous, stale, or inconsistent across surfaces.

Therefore this wave changes acceptance from **presence-first** to **interaction-first** assurance.

## 4. Theme adjudication
The accepted Library donor exposes a true near-black `notion-dark` application theme. The Owner-facing W03 label **Deep Neutral** MUST resolve to that donor-derived deep-neutral behavior through ONE shared theme owner. W03 currently contains duplicate/local theme paths whose effects are inconsistent across surfaces. The correction must eliminate parallel presentation owners rather than patch each surface independently.

## 5. View-vs-Context adjudication
A control styled/labeled as a workspace/view mode changes CENTER. A Context/Inspector lens changes RIGHT Context. It is a defect for a selected workspace-looking tab/navigation item to leave its intended target region stale. This decision applies to Runs, Enterprise, Labs, Scenarios, Results and future surfaces.

## 6. Relation authoring adjudication
Multi-select relation authoring is not satisfied by an exposed `Connect` command alone. Eligible surfaces require a professional relation composer with source/target, relation type/direction and version/revision/working pins where domain semantics require them, with validation and one domain command owner. Visual edges never silently become canonical relationships.

## 7. Operational Surface adjudication
Terminal/Shell is capability-driven. Entry routes converge on `OPEN_TERMINAL`. Operational windows inherit floating/sticky-quality pointer window mechanics. OPS-007 requires a real visible session tab strip/tab-group with switching/reordering; a window presentation button named `Tab` is not sufficient by itself.
