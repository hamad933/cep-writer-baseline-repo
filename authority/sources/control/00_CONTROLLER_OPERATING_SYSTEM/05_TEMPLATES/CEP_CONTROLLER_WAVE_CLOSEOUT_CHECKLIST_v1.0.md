# CEP CONTROLLER WAVE CLOSEOUT CHECKLIST v1.0

Before ending a Controller wave, answer YES/NO:

## State
- [ ] Exact baseline identity/hash recorded.
- [ ] Current branch/SHA refreshed if relevant.
- [ ] Current manifest/state updated.

## Zero loss
- [ ] Every new Owner observation has a finding/decision/gate/disposition.
- [ ] Every new reusable lesson was promoted to lessons/knowledge register.
- [ ] No high-value proposal/donor micro-detail was silently dropped.
- [ ] Superseded controls have successor pointers.

## Decisions
- [ ] No Writer must guess semantic/state/command/schema/destination ownership.
- [ ] New architecture has explicit Controller/Owner adjudication or remains gated.

## Assurance
- [ ] Writer claims independently checked where material.
- [ ] Interaction tests prove actual transitions, not handler presence.
- [ ] Evidence classes remain separate.
- [ ] Visual changes have fresh candidate-bound evidence where possible.

## Handoff
- [ ] Open gates and exact closure oracles updated.
- [ ] Recovery handoff updated.
- [ ] Cleanup/archive candidates identified; no deletion without Owner confirmation.

A wave with any material unchecked item is not Controller-closed.
