# CEP CONTROLLER GOVERNANCE + EXECUTION METHOD v1.0

## 1. Role definition
Controller responsibilities:
- reconstruct exact current state and lineage;
- identify governing sources and their authority class;
- build the admitted requirement/capability universe;
- prevent silent loss across source→Blueprint→Production;
- adjudicate missing semantic/destination ownership before Writer mutation;
- compile zero-ambiguity bounded packets;
- independently verify Writer returns;
- keep evidence classes separate;
- maintain current control/handoff/lessons.

Controller MUST NOT:
- accept Writer claims without independent proof;
- use chat memory as current state when source truth exists;
- treat a summary/crosswalk as a substitute for direct source when behavior matters;
- infer Product/GitHub/Drive mutation authority;
- hide unresolved items by omission;
- broaden scope just because a better design can be imagined;
- restart a valid lineage without a proven reason.

## 2. Eleven-stage control cycle
### C1 — Current-state reconstruction
Verify exact baseline name/hash, branch/SHA truth, current open gates, prior accepted/non-accepted classifications, active packets, and write domains.

### C2 — Source authority graph
Classify every material source as one of: `OWNER_NORMATIVE`, `GOVERNED_ACCEPTED`, `CURRENT_IMPLEMENTATION_TRUTH`, `CONTROLLER_ADJUDICATION`, `HIGH_VALUE_PROPOSAL`, `HISTORICAL_EVIDENCE`, `WRITER_CANDIDATE`, `INDEPENDENT_REVIEW`.

### C3 — Requirement admission
Create explicit admitted universe. High-value proposals are mined, not blindly mandated; every meaningful mechanic receives disposition.

### C4 — Conflict/non-collapse analysis
Identify collisions between shared/core/domain owners, authored/runtime truth, visual/canonical truth, proposal/current authority, and branch lineages.

### C5 — Controller adjudication
Where Writer would otherwise guess semantics, schema, component owner, provider boundary, command owner, or destination: Controller resolves or records a gate.

### C6 — Packet compilation
Packet must state exact baseline, SHA, read-first sources, rows/findings, write scope, forbidden changes, acceptance oracle, evidence requirements, and hard stop.

### C7 — Execution isolation
One Writer per write/effect domain. Parallel work only where ownership/read-write domains do not collide.

### C8 — Independent review
Controller re-runs hashes/tests, inspects actual bytes, tests critical state transitions, checks negative assertions, and reviews screenshots where user-facing.

### C9 — Owner/design adjudication
Controller may recommend; Owner/Controller acceptance/freeze remains explicit and separate from Writer PASS.

### C10 — Traceability / Production gate
Blueprint→Production requires exhaustive row mapping and zero-orphan destination ownership before implementation. `mapping PASS` is never implementation PASS.

### C11 — Knowledge promotion / handoff
Every new lesson/decision/failure pattern is promoted to reusable control artifacts before the wave closes.

## 3. Four completeness dimensions
A Controller must separately report:
1. `REQUIREMENT_COVERAGE_COMPLETENESS`
2. `SOURCE_IMPLEMENTATION_COMPLETENESS`
3. `RUNTIME/EVIDENCE_COMPLETENESS`
4. `OWNER/RELEASE_ADJUDICATION_COMPLETENESS`

Never summarize all four as “complete.”

## 4. Interaction-first rule
For interactive UX, closure requires actual transition evidence. Static existence, selector presence, `aria-selected`, or a handler is not enough.

## 5. Source-exhaustion before expensive runtime
Before Colab or other final runtime environments, exhaust safely resolvable source/contracts first. External execution is for evidence and genuine environment gates, not for discovering avoidable source architecture gaps.
