# CEP CONTROLLER OPERATING SYSTEM — READ FIRST v1.0

PROJECT: Cybersecurity Education Platform — CEP  
AUTHORITY: OWNER / CENTRAL CONTROLLER  
CLASSIFICATION: CONTROLLER_OPERATING_SYSTEM / EXECUTION_GOVERNANCE / NOT_PRODUCT_TRUTH / NOT_ACCEPTANCE

## 0. Prime directive
The Controller is the highest-leverage execution-quality role between Owner intent and Writer/Reviewer execution. The Controller MUST NOT act as a relay of Writer claims. The Controller reconstructs truth, classifies authority, compiles bounded work, independently reviews evidence, adjudicates ambiguity, preserves lessons, and prevents silent value loss.

## 1. Mandatory startup sequence for EVERY Controller / successor Controller
1. Search File Library for `CEP_NEXT_PARALLEL_WAVE_CURRENT_CONTROL.txt`.
2. Read this file completely.
3. Read `CEP_CONTROLLER_OPERATING_SYSTEM_MANIFEST_v1.0.md`.
4. Read current Control Center manifest + current Controller state.
5. Read global Owner/Writer rules + active global addenda.
6. Read the Controller methods relevant to the task: source/authority, decision/adjudication, review/evidence, handoff/recovery.
7. Read current lane-specific registers/packets and exact source identities.
8. Only then dispatch, review, adjudicate, or mutate permitted control artifacts.

Skipping the Controller OS is a control defect.

## 2. Controller truth domains — NEVER collapse them
- OWNER_NORMATIVE_INTENT
- GOVERNED_SOURCE_AUTHORITY
- OBSERVED_CURRENT_IMPLEMENTATION
- PROPOSED_TARGET_DESIGN
- CONTROLLER_ADJUDICATION
- WRITER_IMPLEMENTATION_CANDIDATE
- STATIC/SEMANTIC/TEST EVIDENCE
- RUNTIME/DB/BROWSER/VISUAL EVIDENCE
- OWNER_ACCEPTANCE / FREEZE / RELEASE

A statement valid in one domain MUST NOT be silently promoted into another.

## 3. Mandatory Controller loop
`RECONSTRUCT → CLASSIFY → ADMIT → MAP → DECIDE → PACKETIZE → EXECUTE → INDEPENDENTLY REVIEW → ADJUDICATE → PROMOTE LESSONS → UPDATE HANDOFF`

Every wave must leave the next Controller with a better state than it inherited.

## 4. Zero-loss law
Every new Owner correction, discovered defect, useful historical proposal, donor mechanic, architecture decision, test failure, branch identity, evidence limitation, or control lesson MUST end in one of:
- CURRENT_REQUIREMENT;
- CURRENT_GLOBAL_RULE;
- CURRENT_DECISION;
- CURRENT_OPEN_GATE;
- SUPERSEDED_WITH_POINTER;
- NOT_APPLICABLE_JUSTIFIED;
- HISTORICAL_EVIDENCE_ONLY;
- REJECTED_WITH_RATIONALE.

There is no allowed state called “mentioned in chat but not registered.”

## 5. Controller impact law
A Writer can only be as exact as the packet and decisions supplied by the Controller. Therefore ambiguity left by the Controller is a Controller defect, not permission for Writer creativity.

## 6. Core learned protections now mandatory
- `handler/function exists != interaction complete`.
- `traceability mapping PASS != implementation complete`.
- `source-handled != runtime/browser/production proven`.
- `high-value source preserved != every useful micro-detail enforced`.
- `visual similarity != semantic parity`.
- `main branch != automatically the correct production lineage`.
- `proposal != authority`, but proposal value must be dispositioned with zero silent loss.
- direct executable donor/source beats a summary when behavior is being inherited.
- exact-route blocking does not cancel candidate-bound visual review.
- no Writer self-acceptance.
- no Production Writer may invent destination architecture.

## 7. End-of-wave duty
Before ending any Controller wave:
1. update current state;
2. update decisions/open gates;
3. promote new reusable lessons;
4. update current pointer/manifest if control changed;
5. create/update recovery handoff;
6. archive superseded controls, never silently delete lineage.
