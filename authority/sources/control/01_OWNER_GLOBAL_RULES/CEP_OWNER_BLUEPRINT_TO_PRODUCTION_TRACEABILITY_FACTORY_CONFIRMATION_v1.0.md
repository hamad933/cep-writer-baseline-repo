## 1. Controlling rule

Before ANY Blueprint is converted into Production, the Controller MUST execute a dedicated:

`BLUEPRINT → PRODUCTION TRACEABILITY FACTORY`

This is a mandatory phase and a hard gate. It is not optional documentation.

The conversion contract exists to prevent silent capability loss and to prevent a repeat of Astra Mission #1, where substantial Blueprint value transferred while detailed capabilities remained PARTIAL or MISSING.

## 2. Mandatory execution order

1. Reconstruct current state.
2. Complete Blueprint reconciliation/correction.
3. Complete independent Blueprint assurance.
4. Complete targeted Browser + visual review.
5. Obtain Owner/Controller design adjudication.
6. THEN build the FULL Blueprint → Production Traceability Matrix.
7. Pass `ZERO_ORPHAN_PRODUCTION_TRACEABILITY_GATE`.
8. ONLY THEN prepare Production Writer packets and begin bounded Production implementation.

No Production Writer may infer, invent, or guess destination architecture.

## 3. Row universe

Create one explicit traceability row for EVERY admitted Owner requirement and every admitted capability/behavior, including at minimum:

- commands and command availability;
- pointer, mouse, keyboard and shortcut behavior;
- selection / multi-selection;
- context actions and context menus;
- pane / dock / overlay / drawer behavior;
- visual hierarchy and presentation grammar;
- responsive behavior and preferred-vs-effective state;
- accessibility and focus behavior;
- RTL/Bidi behavior;
- customization/preferences;
- notes / sticky notes where admitted;
- guidance/support UI;
- spatial behavior;
- Operational Surface / Terminal / session behavior;
- donor mechanics admitted through Library/Visualize/other governed donors;
- domain semantics and negative requirements / forbidden collapses;
- authority/provider/platform boundaries.

Historical lineage evidence may support current requirements, but historical/superseded rows are not counted as competing current requirements. Current requirement admission must follow governing supersession order.

## 6. ZERO_ORPHAN_PRODUCTION_TRACEABILITY_GATE

The gate is PASS only when:

- admitted Owner requirements with no row = 0;
- rows with unknown destination ownership/path/symbol that are not explicitly gated/unresolved = 0;
- silent missing requirements = 0;
- duplicate competing semantic/state/command owners without adjudication = 0;
- generic conversion claims without exact row-level mapping = 0;
- unresolved collisions that would make Production Writer guess = 0.

A row may be `AUTHORITY_GATED`, `PROVIDER_GATED`, `RUNTIME_UNPROVEN`, `VISUAL_UNPROVEN`, `NOT_APPLICABLE_JUSTIFIED`, or `UNRESOLVED_CONFLICT` and still remain visible in the matrix, but such a row MUST NOT be silently treated as implemented. If a row blocks safe Production destination ownership, the gate fails until the conflict is resolved or the row is explicitly removed from the admitted Production implementation scope by Owner/Controller adjudication.

## 7. Production packet rule

After the gate passes, Production Writer packets MUST be compiled from the Traceability Matrix. For every production lane, the packet must identify exact rows, files, symbols, state/command/style/API owners, read-only dependencies, write scope, collision boundaries, required evidence, anti-loss tests, and stop conditions.

The Production Writer MUST NOT design destination architecture from scratch.

## 8. Proof rules

Visual similarity alone is never sufficient proof.

Keep evidence classes separate. Static evidence cannot be promoted into runtime/browser/visual proof. Browser screenshots do not prove database/persistence semantics. Production source presence does not prove accepted interaction behavior.
