# MISSION PHASES + GATES

## PHASE 0 — Intake / identity
- verify package manifest;
- verify accepted donor SHA/bytes;
- read authority contract and Owner addendum;
- reconstruct current Control Center state.
Gate G0: `INTAKE_VERIFIED`.

## PHASE 1 — Authority convergence
- reconcile current Owner rules, canonical registry, Controller findings, Big Boss/recovery value;
- update conflict/supersession ledger;
- compile current 23-surface requirement index.
Gate G1: `CURRENT_AUTHORITY_CONVERGED / OPEN_OWNER_CONFLICTS_EXPLICIT`.

## PHASE 2 — Accepted donor zero-loss archaeology
- complete 330-function + component/DOM/CSS/event/state mechanic dispositions;
- identify exact reusable primitives and donor defects/supersessions.
Gate G2: `DONOR_ZERO_LOSS_MINED`.

## PHASE 3 — Foundation contracts
- finalize executable layout/slot constitution;
- component/command/preference/state schemas;
- global + family-engine ownership map;
- 23-surface applicability matrix.
Gate G3: `FOUNDATION_CONTRACTS_COMPILED`.

## PHASE 4 — Executable Foundation v0.1 + Golden Harness
Build the shared foundation using the smallest candidate implementation. Do not yet freeze stack.
Golden Harness must demonstrate components/states/interactions independently of surface domain logic.
Gate G4: `FOUNDATION_V0_1_EXECUTABLE`.

## PHASE 5 — Cross-surface reuse proof
- Library reference proof;
- Learn inheritance proof;
- Visualize spatial proof;
- W03 operational/internal-simulation proof.
No duplicate generic engine is allowed.
Gate G5: `CROSS_SURFACE_REUSE_PROVEN`.

## PHASE 6 — Stack proof + measured recommendation
Compare candidate implementations/dependencies/LOC/glue/build/testability/performance/fidelity.
Gate G6: `STACK_RECOMMENDATION_EVIDENCED / NOT_OWNER_FROZEN`.

## PHASE 7 — Final handoff
Produce final deliverable manifest, open decisions, screenshots/test receipts, Writer-ready contracts/capsule template.
Terminal state:
`READY_FOR_OWNER_FOUNDATION_ADJUDICATION`.
