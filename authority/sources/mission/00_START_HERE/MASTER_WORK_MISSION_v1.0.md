Build CEP once at the shared-mechanic level, then make every surface add only domain-specific semantics.

`GLOBAL EXECUTABLE FOUNDATION -> SURFACE-FAMILY ENGINE -> THIN DOMAIN ADAPTER -> SURFACE COMPOSITION`

This is a reuse-first, Owner-intent-first mission. It is not a migration of failed Production architecture.

## 6. Global layout/slot constitution
A surface may not invent an alternative layout for a shared mechanism merely because it can.

The same shared mechanism should keep:
- presentation grammar;
- location/slot grammar;
- visual structure;
- event semantics;
- state owner;
- input routes;
- customization model;
- responsive model;
- a11y/focus model.

A surface supplies domain-specific labels, commands, content, capability availability and domain adapters.

Exceptions require an explicit `DEVIATION_JUSTIFICATION` record.

## 7. Multiple-route interaction law
For reversible/transient states provide appropriate multiple routes. Examples:
- Command Palette: Esc + visible/pointer route + outside dismissal + selection/commit + appropriate focus/replacement behavior.
- Context menus/popovers: Esc + outside click + command selection + keyboard route.
- Persistent panes: internal close/collapse + external toggle/reveal + command/shortcut/settings route; do NOT close merely on focus loss.
- Dialogs: visible Close/Cancel + Esc; outside click only if semantically safe.

Keyboard accessibility is mandatory, but keyboard must not be the only usable route when a pointer route is appropriate.

## 8. Proof consumers
Do not prove reuse using Library alone.

Required bounded proof consumers:
A. **Library reference consumer** — verifies accepted donor fidelity and structured/editor mechanics.
B. **Learn consumer** — proves maximum Library/editor inheritance plus learning-specific additions without parallel UI engines.
C. **Visualize spatial consumer** — proves shared workspace/action/settings/context plus native spatial-engine candidate; Vue Flow only as a measured alternative, not default.
D. **W03 operational/simulation harness** — proves capability-driven OPEN_TERMINAL, simulated command/state consequence, session identity, tabs/dock/float/split shell; no PowerShell/WSL/PTy requirement for InternalSimulationAdapter.

These may be proof slices/harnesses, not final full surfaces.

## 9. Stack proof
Compare at least:
- Native HTML + CSS + JavaScript ES Modules;
- Native HTML + CSS + TypeScript;
- Vue + TypeScript + Vite only if it materially lowers total complexity.

Specialized candidates are independent admissions:
- xterm.js: terminal rendering only;
- Vue Flow: spatial library only;

Do not select a technology because historical Production used it.

## 10. Assurance

Visual tests must include representative desktop/medium/narrow widths, 200% zoom where useful, LTR/RTL/mixed Bidi, and fresh candidate-bound screenshots.

Golden Harness must make shared component states directly inspectable.
