## OWNER-20260910-010 — GLOBAL_SHELL / SHELL_DESIGN_REOPENED
**Decision:** Current Shell/navigation visual composition is not accepted as strong/final. Mine useful interaction/context mechanics, but redesign global shell/navigation after shared workbench foundation is stable.

**Supersedes:** AppShell/W02Nav REUSE_AS_IS assumptions.

## OWNER-20260910-011 — ALL_SURFACES / GLOBAL_LAYOUT_SLOT_CONSTITUTION
**Decision:** Provide executable universal layout/slot templates. Shared pane/toolbar/context/action surfaces keep the same layout grammar, design language, placement grammar and interaction model; surfaces change domain content/actions only.

**Supersedes:** Surface-local layout invention.

## OWNER-20260910-012 — WORKSPACE_PANES / PANE_SYSTEM_UNIFICATION
**Decision:** LEFT/RIGHT side panes, TOP region and BOTTOM shelf use shared pane/region mechanics. Internal pane close/collapse controls are distinct from external edge reveal/toggle controls. Resize/responsive/preferred-vs-effective behavior is shared.

**Supersedes:** Independent pane mechanics and ambiguous reopen controls.

## OWNER-20260910-013 — TOOLBARS / TOOLBAR_TEMPLATE_UNIFICATION
**Decision:** Use one toolbar template/grammar with stable universal action slots, common behavior/location and customizable composition. Domain actions bind into slots instead of redefining toolbar layout.

**Supersedes:** Different toolbar grammar/placement per surface.

## OWNER-20260910-014 — ACTIONS_TRANSIENTS / ACTION_SURFACE_REUSE
**Decision:** Command Palette, Context Action Menu, Selection Action Surface and similar reusable action containers use common executable templates; only command groups/capability bindings change.

**Supersedes:** Independent menus/palettes per surface.

## OWNER-20260910-015 — INTERACTION / MULTI_ROUTE_REVERSIBILITY
**Decision:** Keyboard is one route, not the only route. Reversible/transient UI requires multiple appropriate reverse/dismiss routes; persistent panes must not disappear merely from focus loss.

**Supersedes:** Escape-only or keyboard-only exit behavior.

## OWNER-20260910-016 — LEARN / MAX_LIBRARY_INHERITANCE
**Decision:** Learn should feel like the Library-grade workbench/editor with learning-specific journey/practice/assessment/lab/progress/recommendation additions; do not resurrect the old consumption-only/no-authoring CENTER restriction.

**Supersedes:** Old Learn no-authoring CENTER / read-only-first authority.

## OWNER-20260910-017 — W03_RUNTIME / INTERNAL_SIMULATION_DEFAULT
**Decision:** W03 default is InternalSimulationAdapter. Container/VM/remote/real-device are optional adapters. Simulated terminal commands operate simulation state; PowerShell/WSL/PTy are not default W03 requirements.

**Supersedes:** Host-shell-first terminal interpretation.

## OWNER-20260910-018 — STACK_PROOF / TECHNOLOGY_MUST_EARN_ADMISSION
**Decision:** Vue/TypeScript/Vite/Vue Flow/Electron/Tauri/Python bridge/SQLite/xterm.js are candidates or specialized tools only; no final stack freeze before measured proof.

**Supersedes:** Historical-stack preservation by inertia.

## OWNER-20260910-019 — WORK_OUTPUT / EXECUTABLE_NOT_PROSE_ONLY
**Decision:** Foundation outputs must be executable/reusable components/templates/cores plus machine-readable contracts and tests, not merely guidelines or reference prose.

**Supersedes:** Documentation-only design system.

## OWNER-20260910-020 — GOVERNANCE / MINIMIZE_WRITER_DISCRETION
**Decision:** Foundation and surface contracts should constrain future Writers so generic design/interaction choices are inherited, not reinvented. Deviations require explicit justification.

**Supersedes:** Writer-local design discretion for shared mechanics.
