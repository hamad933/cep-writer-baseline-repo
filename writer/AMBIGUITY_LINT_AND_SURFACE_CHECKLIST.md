# Writer ambiguity checks

1. Every mechanic has a profile classification and a reason. Omission is a failing contract, never N/A.
2. Distinguish conceptual admission, source preservation, executable binding, tested behavior and Owner acceptance.
3. Define exact selected object, source revision, representation id, session id and invocation id. Do not merge them.
4. Define unavailable/empty/stale/error separately. No fake success and no unknown-green status.
5. Every command has one semantic owner and availability reason. Entry routes call that owner.
6. Every transient has visible exit plus keyboard exit and a deterministic focus result. Persistent panes do not blur-dismiss.
7. Check preferred/effective customization separately at desktop, medium, narrow and useful 200% zoom. A CSS zoom experiment is not evidence of browser zoom.
8. Use the shared slots and styles. A screenshot resemblance alone does not establish reusable ownership.
9. Use UnifiedEditor for applicable working content, including Learn and Notes. Do not recreate a text editor locally.
10. Separate authored definition, runtime mutation, recorded output, evidence admission, review decision and Mastery.
11. Record real provider capability. InternalSimulationAdapter is a complete valid default for bounded simulation; a terminal renderer is not a provider.
12. Read the open-issues ledger before expanding scope. An implementation gap is Writer work, not automatically an Owner question.

Run `npm test` and `npm run check`. Extend the relevant negative oracle only when behavior changes. Capture affected consumer interactions and fresh screenshots. Update profiles and source pointers with the code, not afterwards from memory. Never mutate the Control Center or publish/merge/release from this capsule.
